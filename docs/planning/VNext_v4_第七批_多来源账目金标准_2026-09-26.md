# VNext v4.0 第七批：多来源账目整理金标准

日期：2026-09-26
分支：`fix/rc-full-gate-real-db-concurrency`

## 首轮审计结论

- 既有 `finance.abnormal_transaction@2` 可复用 `ANOMALY_DETECTION` 策略、账单汇总、ActionResolver、Execution、Verification 和消费者结果投影；不新建财务执行引擎。
- 既有文件导入可提供用户授权的账单记录，Android 通知会先进入收据/候选事实；通知文本不能直接成为 Truth。
- 原有 Reality Pipeline 包含证据 hash、Candidate、Truth Version 和 provenance，但交易规格缺失稳定的跨来源身份合并规则。

## 增量合同

- 新增 `finance.abnormal_transaction` Scenario Contract V2，仍指向不可变的 V1 revision 2。
- 支持的证据模式是 `MANUAL / FILE / NOTIFICATION / OFFICIAL_API / INTERNAL`。各来源都必须先保留证据、账号归属和事实版本。
- `transactionId` 是唯一允许的自动跨来源匹配键。缺少该键时，金额、商户、时间只作为展示线索，绝不作为合并依据。
- 退款/冲正需显式 `transactionState` 与 `relatedTransactionId`；没有这些证据不推断关联交易。

## 真实验收边界

- 确定性 MySQL 回归可验证：规格校验、Candidate→Truth 边界、交易身份匹配、历史 Plan Offer 兼容。
- Android 通知来源、真实银行/支付 Provider 和远端 CI 均为 `EXTERNAL_ACCEPTANCE_PENDING`；本地模拟不等于真实授权验收。
- 不开启自动转账、自动支付或任何资金划转。
