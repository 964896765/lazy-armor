# VNext v4.0：64 个新增场景候选去重台账

本台账覆盖总方案附录 A.2 的全部 64 个 proposed key。结论仅用于 Contract V2 评审，不注册 canonical 场景，也不表示产品、用户或真实来源已经可用。

## 判定标准

- **保留评审**：存在独立管理对象，或 Fact/Action/Verification 合同与现有场景具有实质差异；仍须补齐真实来源与合规证据。
- **合并 Recipe**：更像既有场景的参数、策略、模板或跨对象视图，不应为了达到 160 强行造新 key。
- **待调查**：独立性可能成立，但合法来源、隐私边界、业务终态或执行可行性尚不清楚。

## 汇总与准入门槛

初审结果：**38 条保留评审、16 条合并 Recipe、10 条待调查，共 64 条**。这不是最终批准结论。

候选进入 canonical registry 前必须同时满足：

1. 与旧 96 不只是策略、提醒频率、筛选条件或 UI 文案差异。
2. 有版本化 GoalSpec、ResourceSubject、FactDemand、ActionDemand、Verification Contract。
3. 明确 Catalog、产品实现、用户授权、设备在线、Truth 新鲜、可执行、已验证七个不同状态。
4. 至少提供 deterministic sandbox 证据；涉及真实来源/动作时，分别通过真实账号或真机验证后才升级治理状态。
5. 高风险动作仍由既有 Risk/Approval/Execution 权威链处理，AI 只能提出候选。
