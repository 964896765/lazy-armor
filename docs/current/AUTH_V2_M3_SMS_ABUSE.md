# Auth V2 · M3-04 短信请求异常与防滥用

日期：2026-10-14。基线0a943cac，分支codex/v83-persistent-runtime。本批完成服务端请求异常限制、客户端随机标记、隐私告知及过期清理，不改变User ID、绑定证明、Session或Runtime高风险授权。新增0096仅在独立test库执行；个人/生产未迁移或启用，未发送真实短信/邮件。

## 实际保护范围

短信原有号码间隔、号码/IP日额度和最高费用预留继续由0094保障。本批在费用预留前增加同一客户端短期发送次数、多号码请求、IP/请求环境变化，以及服务器IP多号码请求的持久统计，覆盖匿名登录和邮箱/手机号绑定、换号的所有短信OTP用途。安全通知仍使用自己的固定模板和原费用预算，不作为交互验证码请求。

AUTH_SMS_ABUSE_GUARD_ENABLED默认false。启用前要求0096可读以及独立稳定的AUTH_SMS_ABUSE_SECRET，不可复用JWT、短信额度密钥或验证码网关令牌。关闭保护停止新增统计；短信发送开关独立，停发短信时邮箱仍按原认证/限流机制可用，已经签发的合法OTP仍可验证。没有新增验证码展示、人机验证假按钮或另一套账号。

| 规则 | 默认策略 |
| --- | --- |
| 客户端请求次数 | AUTH_SMS_CLIENT_SEND_LIMIT=5，十分钟内累计发码尝试，包括号码冷却/费用预算拒绝前的风险检查 |
| 客户端不同号码 | AUTH_SMS_CLIENT_PHONE_LIMIT=3，十分钟内最多3个号码 |
| 服务器IP不同号码 | AUTH_SMS_IP_PHONE_LIMIT=5，换客户端标记不能重置同一IP的记录 |
| 客户端IP/环境变化 | AUTH_SMS_CLIENT_IP_LIMIT=2、AUTH_SMS_CLIENT_AGENT_LIMIT=2，十分钟内不同IP或User-Agent请求信息过多则等待 |
| 拦截等待 | 新异常等待十分钟；重复请求不延长已有等待，过期后开始新窗口 |
| 数据库入场上限 | AUTH_SMS_RISK_DAILY_REQUEST_LIMIT=500，中国自然日全通道风险请求上限；达到后不增加客户端行或事件 |
| 短期入场 | Redis全通道100次/分钟，加上原OTP/IP限流；Redis丢失不清除SQL日上限 |
| 留存与清理 | AUTH_SMS_RISK_RETENTION_DAYS=7，允许1–30天；Outbox Worker按小时分批清理过期记录 |

阈值是Beta保守配置，需要真实灰度校准NAT、移动网络切换及误拦截率。它们识别请求异常线索，不证明同一个物理设备、实人或账号所有者。客户端可以修改/重置标记或User-Agent；因此始终同时保留服务器IP、SQL总入场及独立短信费用预算。分布式机器人、人机验证和真实设备证明仍需独立能力，不把本批统计描述成硬件认证。

## 上下文、存储与并发

AuthModule的请求中间件用AsyncLocalStorage隔离每次HTTP请求的x-auth-client-id与User-Agent；不修改CurrentUser、JWT主体或可信设备。IP取Nest/Express的服务端请求地址，只接受已有TRUSTED_PROXY_CIDRS策略认可的代理；不读取客户端声明的IP字段。IPv6及映射IPv4地址规范化，等价表示共享统计。DTO拒绝客户端额外提交clientId、trustedDeviceId、用户或用途字段。

客户端自动为/auth/请求附上随机标记。Web只在内存保存；原生使用独立SecureStore键，启动时替换超过30天的标记，账号切换不重置。读取合并并发，存储挂起一秒后使用稳定内存标记；它不是登录令牌，也不授予可信设备或付款权限。Auth请求客户端总时限增至16秒，覆盖新增SQL检查及原短信链路。

0096_sms_request_risk.sql新增auth_sms_risk_subjects与auth_sms_risk_events。表内只保存命名空间、用途、决策/原因、次数、时间及独立密钥HMAC后的客户端/IP/号码/环境指纹；不保存原号码、原IP、原客户端标记、User-Agent原文、验证码、密码、JWT或网关令牌，也不把匿名指纹关联为新的User ID。

事务固定按中国自然日总量→客户端→IP顺序锁定，数据库UTC时钟决定十分钟窗口和等待时间，行锁之后再次读时钟。跨午夜等待回滚旧日并重算；应用时间变化不能重置窗口。拦截结果先提交统计/事件，再在事务外返回SMS_RISK_BLOCKED，避免抛异常回滚导致每次都能重试。日入场上限达到后不继续增大事件和主体基数。

风险SQL共用两秒截止时间。失败返回脱敏503，不预留费用、不创建OTP、不等待恢复后补发；迟到风险事务可能留下保守记录，但调用链不再发送短信。真实SMS网关与0094费用记录仍按原策略执行，UNKNOWN不退款或自动重发。

## 清理、页面与部署

Outbox Worker每小时最多清理1000条旧事件和1000条旧主体；只针对自己的namespace。删除主体前再次核对更新时间，正在使用的窗口/等待不会因扫描与请求竞争被删除。保护开启时自动安排清理；停用保护后重启既有环境，应保持AUTH_SMS_RISK_CLEANUP_ENABLED=true以继续清理，此模式不要求风险密钥或短信发送。默认关闭保护/清理的旧环境不因缺0096停止邮箱登录。

登录页读取实际保护能力和服务端留存策略，展示短信等待与邮箱/密码备用提示，按照retryAfterMs禁用发送。切换邮箱清除短信等待，已绑定邮箱验证码进入原UID。隐私说明补充随机标记、网络来源和请求环境信息的用途；此短信防护不读取指纹、人脸、硬件序列号或安装列表。已有总体IP限流仍适用，不能保证共享IP达到总限流后邮箱无限可用。

灰度顺序：本环境备份/恢复及0093–0095前置验收→0096→稳定namespace/独立密钥→更新客户端→有限开启保护→真实设备、NAT、运营商及误拦截率评估。全部API副本应采用一致的保护策略；已启用0096的环境停止新统计后仍须按策略清理。不得删除当前日总量或轮换namespace/密钥来“解除限制”；0094费用预算必须保留。
