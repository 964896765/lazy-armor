# P4 Plan Detail / 计划体验优化 — 设计准备

2026-10-09：DESIGN_ONLY。P1/P2 已 CLOSED，P3 仍 IN_PROGRESS。本文准备后续 P4 的用户体验与信息语义，不表示已经改页面、增加 API、部署或完成验收。既有实现与真实证据见 [PLAN_CONTROL_SURFACE.md](PLAN_CONTROL_SURFACE.md)。

P4是P3关闭后的第一个正式前后端同步阶段。后端复用/完善只读Plan Experience Projection，移动端同时完善计划列表/详情及日程、会话中的关联状态；遵循 [总计划](V83_MAINLINE.md) 和 [Mobile Product System Track](MOBILE_PRODUCT_SYSTEM_TRACK.md)，不是独立UI美化批次。

## 页面要回答的问题

计划详情回答：“这件事现在帮我做到哪一步，接下来会怎样，有没有需要我处理的事？”用户看到目标、当前进展和现实结果，系统内部执行对象不成为主页面内容。

页面只服务 Persistent Plan。一次性个人事项继续使用轻量 USER_EVENT 详情；临时查询结果留在原会话。

## 主表面与展开层级

| 区域 | 主表面内容 | 语义来源 |
| --- | --- | --- |
| 顶部 | 简短目标名称、运行/暂停/结束状态、有依据的下一次检查时间 | 当前 Plan 及 active PlanVersion 的只读投影 |
| 目标 | 一句话说明系统持续帮用户做什么 | 用户已确认的目标与规则 |
| 当前进展 | 正在检查、等待资源、等待新线索、待核实、需确认或核对结果；一句下一步 | 当前资源门、当前读取/判断/审批/核对状态 |
| 需要你处理 | 缺少的许可、候选核实、合法审批入口；无待办时隐藏 | 当前未解决的 ResourceGap、Candidate 或 Approval |
| 最近发现 | 最近已核实事实或已提交提醒；缺数据时明确授权范围 | 当前相关且有效的 Truth 与正式结果 |
| 最近一次 | 最后一次实际检查时间及用户可理解的结果摘要 | 当前版本已完成的真实读取/运行记录 |
| 执行历史 | 按时间展开“检查通知、等待核实、发现异常、提醒已保存”等摘要 | 不可改写的历史结果，注明发生时点 |
| 信息与资源 | 京东通知、Android 设备、当前读取能力及最近证据时间 | 与当前版本绑定的真实来源和能力投影 |
| 方法 | 已引用的方法及来源；没有实际 Skill 引用时显示自定义规则 | 已冻结的引用；不制造 SkillEntryRevision |
| 设置 | 时间与频率、规则、通知、自动化与确认、版本、暂停/恢复 | 既有合法计划控制与版本变更入口 |

主表面不展示 Invocation、Ledger、epoch、Worker、lease 或技术步骤列表。历史记录呈现用户能理解的动作与结果，不把原始 Runtime 日志换一个标题继续铺满页面。

下一次时间必须有当前版本的调度依据，并使用计划时区。不具备确切时间时显示“等待新的物流线索”，不能用旧 nextRunAt、旧版本记录或设备心跳猜一个检查时间。

## 京东通知计划示例

以下是设计示例，不是新的真机验收截图。时间来自实际投影时才显示。

```text
京东快递异常提醒
运行中 · 等待新的物流线索

目标
有已核实的京东快递异常时提醒我

当前进展
京东通知当前可读取
最近检查：今天 10:30
等待新的物流变化

最近发现
本次授权读取范围内暂无已核实物流线索
这不能证明没有快递

最近一次                              >
今天 10:30 · 已检查，读取到 0 条线索

执行历史                              >
信息与资源                            >
方法                                  >

设置
时间与频率                            >
规则与确认                            >
通知                                  >
版本                                  >

暂停计划
```

“已连接京东”不足以证明能读取。只有当前系统权限、用户来源许可、采集开关、监听健康、设备身份及新鲜证据全部满足时，才显示“当前可读取”；过期后明确显示等待恢复。

## 状态与文案边界

| 实际情况 | 用户表达 | 显示限制 |
| --- | --- | --- |
| 权限/来源/采集/设备任一门未满足 | 等待资源恢复；说明当前缺什么及正常设置入口 | 不用过去的 HEALTHY 掩盖当前缺口 |
| 受控读取尚未完成 | 正在检查京东通知 | 不预先显示检查成功或最近检查完成时间 |
| 当前范围 VERIFIED_EMPTY | 暂无已核实物流线索，等待新线索 | 不显示“没有快递”“无异常”或“未发现变化”作为现实结论 |
| 新线索未核实 | 有物流线索需要核实 | 不把 Candidate 显示为可信快递状态 |
| 有有效且已核实的普通物流 Truth | 显示该条线索的已核实状态，继续等待 | 不扩大为所有快递均正常 |
| 有满足规则的有效异常 Truth | 显示具体异常、来源、时间及已产生的处理结果 | 提醒未提交前不能显示“已提醒” |
| 执行结果未知或核对中 | 正在核对实际结果 | 不显示成功，不引导重复执行副作用 |
| 当前已暂停/结束 | 已暂停/已结束，保留历史检查和结果 | 不显示仍会检查或提示重新授权后自动运行 |

“最近检查”取实际读取完成时间，不取 Worker 心跳或来源列表刷新时间。“未发现变化”只有存在可比较的已核实前后状态时才成立。历史事实后来失效时仍保留历史记录，但不能继续作为当前状态。

站内提醒已持久化只能表达为“已生成站内提醒”；没有送达/阅读证据时不宣称手机系统已通知或用户已处理。

## 操作与权威

页面复用现有 owner 校验和只读 control projection，不新增计划、来源、Truth 或调度权威。页面打开和展开记录不授权外部操作。

编辑目标、规则或频率走合法草稿/确认与新版本流程；不能直接覆盖已确认 PlanVersion。没有现成编辑合同的设置项沿用计划会话入口。暂停/恢复沿用现有控制合同，历史结果不删除。

“检查一次”是否可用继续由现有运行状态、风险及确认政策决定。页面不绕过正在进行的审批/核对，也不因为改成普通中文按钮就允许重复副作用。

## 后续 P4 验收方向

P4 DoD至少真机覆盖九种状态：运行中、WAITING_RESOURCE、VERIFIED_EMPTY、Candidate待核实、Truth有效、Approval待处理、结果核对中、暂停、结束。验证对应页面表达/操作与Authority一致，时间/版本/来源归属正确。缺少真实Skill引用时不伪造方法卡片；能力不可用或历史证据失效时不冒充当前可用。Contract、Runtime、Product、Real Evidence四项DoD与总Gate齐全后才P4 CLOSED。

这些是 P4 的设计验收方向，不加入 [P3 的三个关闭条件](P3_RESOURCE_GAP.md#2026-10-09-冻结的剩余关闭范围)，当前不做页面或 Runtime 实现。
