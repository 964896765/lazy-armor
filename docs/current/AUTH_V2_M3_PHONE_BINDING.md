# Auth V2 · M3-01 手机号安全绑定与当前分析

日期：2026-10-13。基线4c3f2cf6，分支codex/v83-persistent-runtime。范围：已登录用户通过当前账号证明与新手机号验证码，将手机号添加到原User ID，并同步更新安全中心。零新SQL，复用login_identifiers、password_credentials、原Session和审计。正式短信推广、换号、丢失号码恢复及Passkey分别待实施或验收。

## 实际行为与页面

密码用户先验证当前账号密码；无密码用户通过本账号已验证邮箱或手机号获取验证码。当前账号验证通过后，才允许向已冻结的新手机号发送第二个验证码。号码规范为+86与合法11位大陆号码，其他地区或格式拒绝。验证码与绑定证明由服务端单次消费，成功添加已验证phone映射及LOGIN_PHONE_BOUND审计。

绑定后手机号验证码与已有邮箱验证码进入同一用户；在UNIFIED模式下，已设置的密码也可通过该手机号登录。无密码用户仍无密码，不因绑定而生成密码。原邮箱、User ID、个人资料、订阅与业务数据归属保留；被其他账号或本账号占用的号码拒绝重复添加，不覆盖、不转移、不自动合并。

安全中心按phoneBinding.available显示“添加登录手机号”；邮箱和手机号共用两步表单，分别核对目标渠道和验证码。绑定证明只在页面内存中持有，不放URL或持久化存储。离开页面、会话变化、过期或503后清理证明；异步晚到结果不能恢复旧证明。绑定完成后读取服务器状态，显示脱敏手机号及实际共用密码状态。Beta登录页仍默认邮箱验证码；密码页已有手机号次级入口按服务端能力显示。Passkey保持待开放说明。

## 共用流程与兼容性

IdentifierBindingService提取原邮箱绑定的安全流程，EmailBindingService/PhoneBindingService仅适配目标类型与配置。邮箱旧路由、email-binding Redis命名空间、HMAC用途、状态中的email字段及OTP上下文保留；本批用已部署M2格式的持久化证明与验证码完成兼容回归。新增phone-binding命名空间、phone状态与phone-bind-current/phone-bind-target用途，不能互相兑换。

| 接口 | 证明与结果 |
| --- | --- |
| GET /auth/security/methods | 当前Session，返回phoneBinding.available与可发送的已验证源渠道 |
| POST /auth/phone-binding/start | 当前Session；phone、proof及一种密码/源identifierId证明；冻结目标、用户、Session与凭据版本 |
| POST /auth/phone-binding/current/confirm | 仅current阶段；验证已有渠道OTP后提升到target，不延长原证明期限 |
| POST /auth/phone-binding/target/request | 仅target阶段；重新核对会话/密码/源渠道/目标占用后发送新号码OTP |
| POST /auth/phone-binding/confirm | 新号码OTP；Redis单次消费后事务锁定重查、添加原账号映射与审计 |

证明10分钟、OTP5分钟；绑定冻结密码凭据hash/version指纹，包括无密码状态，并冻结源标识归属与verified状态。跨用户、跨Session、刷新/退出/禁用/SQL会话过期、首个密码设置、密码版本或源归属变化均不能继续。Redis只存短期证明及指纹，不存密码/hash/验证码，key中不含原始证明或号码。

目标唯一索引的缺失键锁与匿名OTP采用同一顺序；最终写入和成功审计同事务。竞争只允许一个归属，匿名OTP若先建号则绑定冲突；绑定先成功则匿名OTP进入原账号。外部验证码发送与消费在SQL重试外，SQL或审计失败回滚标识并消耗证明，必须重新开始双证明。基础设施错误返回脱敏503。

邮箱/手机号绑定共用当前账号尝试预算10/300秒和IP20/300秒，防止切换目标类型绕过密码尝试预算。OTP发送标识1/60秒、IP10/600秒跨用途共享；验证码验证保留上下文5/300秒及IP30/300秒的窗口预算。本批还修复了跨五分钟边界可重置同一验证码尝试次数的问题：额外Lua原子计数随实际OTP剩余TTL过期，每条验证码最多尝试5次，包括成功尝试；跨窗口后的第6次即使输入正确仍返回429。不同验证码digest分别计数，相同值不重置已有次数，原M2字符串验证码保持可读。发送预算仍是固定窗口，尚非严格60秒间隔；日费用额度、设备异常及供应商熔断属于下一批正式短信防滥用。

## 配置、上线与回退

AUTH_PHONE_BIND_ENABLED默认false；true要求AUTH_PASSWORD_CREDENTIAL_MODE=UNIFIED，否则启动拒绝。入口还要求SMS_LOGIN_DELIVERY_ENDPOINT为HTTPS并有LOGIN_CODE_DELIVERY_TOKEN，availability为CONFIGURED；本地控制台短信不开放手机号绑定。CONFIGURED只证明网关配置可用，不证明供应商签名/模板、运营商送达或真实费用已验收。正式网关必须支持新OTP用途，发送拒绝重定向，失败删除验证码且不回退控制台。

0093全量迁移、回填一致性、统一模式灰度仍需按每个环境独立验收，本批只在新建test库验证。先完成供应商、防滥用和恢复策略，再开放真实号码灰度；不以本批测试替代正式上线。故障时关闭手机号绑定开关，会拒绝所有未完成证明；已有合法手机号登录映射保留，原邮箱和Session继续遵守原策略。不要删除phone映射、降级到旧账号解析代码或自动合并用户。关闭绑定开关不等于停止匿名短信登录发送，后者需要网关及发送预算的独立控制。

本人库不迁移、不回填、不修改角色或业务资料；不部署生产、不安装新APK。登录成功或手机号绑定不会授予付款、群发、删除等Runtime敏感操作权限，仍需原具体操作审批。

## 当前项目分析与下一批

账号一致性的实现已覆盖邮箱、手机号与用户级密码；安全绑定在已有账号上添加凭据，减少多套账号和数据分裂风险。复用绑定流程与表单，降低两种渠道安全逻辑逐渐不一致的维护风险。认证功能有隔离验收，但个人/生产环境仍未启用这些迁移与新入口，不能宣称整体Auth V2或Beta发布完成。
