# Auth V2 · M3-03 手机号安全更换与旧渠道通知

日期：2026-10-14，工作始于2026-10-13。基线3400cad1，分支codex/v83-persistent-runtime。本批沿用一个不可变User ID和原双证明引擎，实现手机号替换、旧号码停用、全部登录会话撤销、持久安全通知及同步页面。0095仅用于独立test库；个人/生产未迁移或启用，所有外部发送均为fixture。

## 用户行为与权限

安全中心仅在UNIFIED、真实短信配置、安全通知配置及独立换号开关均可用时显示“更换登录手机号”。先选择当前账号要停用的已验证号码，再用当前密码或已验证邮箱/手机号验证码证明当前账号，最后验证新号码。无密码用户无需为换号临时设置密码。新号码被任何账号占用时拒绝，不合并账号、不转移目标或订阅。

完成后原号码停用，原账号、资料、目标、记忆、订阅和密码保留。所有登录设备需重新登录，客户端清除令牌与当前账号查询作用域，登录页明确引导使用新号码或已绑定邮箱进入原账号。通知显示等待、请求中、网关受理、未知或受阻；受理不代表运营商/邮件送达。

换号需有可证明的当前账号。仅收到新号码验证码不能恢复旧账号；全部旧渠道和密码都丢失时，此入口不能替代恢复流程。付款、群发、删除及其他Runtime高风险操作仍依原审批和授权，不因换号或登录自动获得权限。

## 接口、证明与事务

新增POST /auth/phone-change/start、/current/confirm、/target/request、/confirm。start增加oldIdentifierId，其他步骤只接受服务端challenge和验证码；客户端不能在后续请求修改旧号码、新目标、用户或Session。

共用IdentifierBindingService，新换号使用独立Redis namespace、HMAC域和phone-change-current/target用途。旧邮箱绑定的namespace、密码指纹和scope数组格式保留；不会把旧添加邮箱/手机号挑战解释为换号授权。十分钟证明冻结userId、sid、旧号码映射ID/验证版本、新号码、密码状态/版本及当前证明源。每一步重查有效Session和账号状态；设置首个密码、改密、标识版本变化、刷新、退出或过期使旧证明失效。

目标OTP保持300秒、原子单次消费及实际OTP最多5次尝试，固定窗口变化不能恢复次数。最终Redis挑战在SQL前原子消费；SQL失败也不能复活旧证明，需重新完成两次验证。

最终事务按现有唯一索引锁策略锁定新号码，重查当前账号/会话、密码和旧映射，再完成以下动作：

1. 为旧映射设置disabled_at，保留其唯一归属记录。
2. 插入新号码的已验证映射，归属原User ID。
3. 撤销全部auth_sessions及尚未消费的密码恢复链接。
4. 冻结原号码与已有已验证邮箱，写入安全通知任务。
5. 写入LOGIN_PHONE_CHANGED审计。

上述动作全部提交或全部回滚，外部HTTP不进入数据库重试事务。同一旧号码的并发换号只有一个成功。用户行锁与原会话创建/刷新策略共用；额外修复匿名OTP在“解析身份→签发会话”之间的竞态，签发时重查映射ID、验证版本和停用状态，旧号码解析结果不能在换号完成后补发Session。密码登录、当前渠道证明、安全中心也拒绝/过滤停用号码。

## 旧号码与迁移边界

0095_phone_change_security.sql为login_identifiers添加可空disabled_at，并新增auth_security_notices。已有标识、User ID、hash和资料不重写。新版认证在启动时核对列和通知表；即使换号开关关闭，也必须先执行本环境的0095，避免启动成功后邮箱/手机号请求因缺列失败。

旧号码保留唯一索引记录，既不能重新登录原账号，也不能通过匿名OTP或另一账号绑定自动取得该号码。此版本没有按时间自动释放号码：号码回收、误换号撤销、停用号码重新分配、个人信息留存/删除与客服核对属于独立受控流程，尚未实现。不能直接删除停用记录来绕过保护。

灰度前需本环境备份/实际恢复、0093回填核对及UNIFIED验收、0094短信预算与供应商验收、0095、独立安全通知模板/网关和Outbox Worker验收，再有限开放AUTH_PHONE_CHANGE_ENABLED。两个新开关默认false；关闭换号停止新增证明，关闭通知停止新发送，但已保存状态仍可读取。已经停用旧号码的库不能回退到忽略disabled_at的旧认证代码；故障时停入口、保留安全读取、向前修复。

## 持久安全通知

现有业务通知的外部适配器仍是No-op，本批使用独立SecurityNoticeService，避免声称该适配器已发送旧渠道通知。任务在换号事务内写入SQL，由outbox-worker角色每5秒领取最多8项，API角色不定时外发；明确开发集成角色可按原workerEnabled策略运行。

收件人和旧/新号码脱敏参数使用AES-256-GCM封存，复用CREDENTIAL_MASTER_KEY，AAD绑定任务、用户、事件与渠道。客户端只看到脱敏收件人、状态和时间，不返回密文、原号码、网关令牌或供应商标识。仅向本次停用的原手机号及既有已验证邮箱排队，未经验证的历史邮箱不作为通知对象。换钥前必须处理待发密文；无法解密的任务受阻，不重新解析收件人。

独立AUTH_SECURITY_NOTICE_ENDPOINT必须HTTPS、拒绝重定向/内嵌URL凭据；AUTH_SECURITY_NOTICE_TOKEN至少32字符，配置已审核的PHONE_TEMPLATE与EMAIL_TEMPLATE。POST为type=security_notice、contractVersion=1、purpose=phone-changed，固定requestId/Idempotency-Key为任务ID，eventId关联同一次换号；模板参数仅脱敏旧号/新号，不接受任意营销正文或验证码。

手机号通知复用0094的持久号码/IP/通道额度与最高费用预留，用途security-phone-changed；正文增加smsBudgetRequestId、budgetDay、maxCostFen。OTP网关仍使用V2，并新增phone-change-current/target用途，不借OTP模板发送安全通知。网关须在发送前按真实片数报价拒绝超价、持久去重，并返回accepted、匹配requestId、合法providerRequestId以及短信整数costFen≤预留。实际账单及运营商/邮件送达仍待独立核对。

| 任务状态 | 实际含义与后续 |
| --- | --- |
| PENDING | 已持久保存，等待发送；尚未发送的额度拒绝可按真实等待时间有限重试 |
| CLAIMED | SQL条件领取成功，正在处理；并发Worker仅一个取得任务 |
| ACCEPTED | 合法网关回执和状态已保存；仅表示受理，非已送达 |
| UNKNOWN | POST失败、超时、回执不合法/超价、状态未确认，或进程领取超过60秒；不自动重发或退款 |
| BLOCKED | 密文无效、配置受阻或最多5次发送前重试耗尽；保留证据，需运营核对 |

HTTP请求与响应体共用4秒时限，迟到结果不能把UNKNOWN改为ACCEPTED。发送前额度拒绝才允许重试；已尝试外发或领取超时均保持未知，避免进程恢复重复发短信。已预留费用不退款；停发开关在预留后再次核对。安全通知发送失败不撤销已经提交的换号，不假报送达，也不授予额外业务权限。
