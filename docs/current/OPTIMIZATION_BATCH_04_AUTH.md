# 第四批 · Auth V2 Beta 统一邮箱与登录设计

日期：2026-10-13；分支 codex/v83-persistent-runtime。上批基线 5a85c31。对应 FIX-06、FIX-07 与 FIX-08 的会话刷新切片；全 Auth V2 与正式发布仍有独立后续阶段。实施路线见 [Auth V2 方案](AUTH_V2_IMPLEMENTATION_PLAN.md)。

## 变化与结果

同一规范化邮箱的密码注册与验证码注册共同检查、锁定原身份唯一索引；先验证码注册后不能再创建密码账号，而是已登录后验证邮箱验证码设置可选密码。先密码注册的旧邮箱未经验证，不允许匿名验证码接管；本人用原密码登录、再确认用途和当前用户绑定的邮件验证码，将邮箱映射到原 User ID。历史不同 User ID 冲突返回 IDENTITY_CONFLICT；不迁移、合并或删除任何原账号。

密码重置条件领取尚未使用且未过期的 token，密码更新、全会话撤销、其他恢复链接失效与审计同事务；审计失败全部回滚。创建/刷新 Session 与改密/重置按用户锁协调，并重查已经比较的原密码 hash，阻止旧密码请求在重置后补发 Session。未验证邮箱不是恢复渠道；改密发生在恢复邮件发送途中时也不允许晚到 token 新建。新密码限制 bcrypt 的 72 字节覆盖范围，旧登录保持兼容。

登录页默认邮箱验证码，手机号 tab 展示真实服务状态，OTP 登录和注册合一，密码是次级入口。独立密码注册页转向 OTP。安全中心从后端读取脱敏标识、验证状态及密码状态；增加本人旧邮箱验证与首个密码设置页面。Passkey 标明后续开放；手机号优先生产入口尚未切换。

补齐忘记密码申请与恢复深链表单，允许已有原生会话打开恢复链接；服务器仍要求有效单次恢复 token，完成后全设备退出并以新密码登录。申请回包保持统一，不泄露邮箱是否存在；恢复邮件发送要求 HTTPS 且禁止重定向。

透明 Refresh 不再清空聊天 input、附件和工作区；明确登录/退出变化才改变 sessionScope 与查询缓存。SecureStore 写操作串行，旧刷新结果不能复活已退出账号；成功同账号轮换保留短期可信设备证明，但服务器仍复核实际撤销。改密后包括当前设备在内的所有会话退出。

真实 Web 窄屏检查还发现背景图溢出，已约束背景容器并修复。原五个一级页与 Runtime/Risk/Approval/Truth 权威保持。

## 历史库与迁移边界

使用 scripts/audit-auth-identities-readonly.mjs 对根 .env 指向的本地库运行 READ ONLY 一致性快照。查询不读取 password_hash、JWT 或 Refresh Token。私有报告 artifacts/auth-identity-audit-20261013-01.json 仅保存聚合和每次加盐指纹。

本地结果：11 个旧密码凭据、1 个已验证标识、10 个旧密码邮箱未验证；跨账号冲突 0、非规范标识 0。结果只代表该本地快照，不代表生产历史账号已经完成迁移。未改写任何本人账号、资源、角色或 Session。

零新 Schema/SQL，保持 93 条原迁移。密码凭据解耦、手机号正式供应商/绑定/换号、任意新邮箱绑定、Passkey 与人工账号恢复工具继续独立实施。
