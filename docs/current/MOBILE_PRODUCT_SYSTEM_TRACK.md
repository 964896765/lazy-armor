## 一级结构与可演进范围

一级页面名称、数量、顺序和职责永久冻结为：日程 | 计划 | 会话 | 资源 | 服务。Skill仓库归计划，MCP归资源→接口，Windows归资源→其它设备，Cloud能力归资源，现实服务归服务。内部导航、搜索、详情和设置属于二三级页面，不因此新增一级入口。

二三级页面、信息层级、组件、视觉、交互、空/加载/错误状态及恢复路径持续演进。每个新能力的设计先写清其五页归属、用户关心的进展、需处理的事项和来源证据，再接API投影，不直接铺技术对象。

## 共用语义与交互

| 基础件/状态 | 统一要求 |
| --- | --- |
| PageShell / TopBar | 标题、返回层级、安全区域、主要操作的位置一致；返回不丢失原Goal上下文 |
| Section / Row / Divider | 同层级信息用一致排布与密度；普通列表不强制卡片化 |
| Tabs | 相同层级切换保持统一含义，一级顺序不变 |
| Status / InlineNotice | 状态名称、重要度、说明与下一步一致；颜色不承担唯一含义 |
| ActionSheet / Confirm | 明确将发生的用户动作、范围与可撤销性；区分内部编辑与外部副作用 |
| Approval | 显示具体对象、平台、动作和风险上下文；确认草稿不冒充批准执行 |
| ResourceState | 连接、权限、授权、健康、采集开关与新鲜证据分开；历史可用不代表当前可用 |
| CandidateState | “待核实线索”与“已确认事实”分开；显示合法核实/否认入口 |
| TruthState | 当前有效事实与历史/过期/撤回事实分开，呈现来源与观察时间 |
| ResultState | 执行完成、核对中、已验证、待处理分别表达；不把ACK作为验证 |
| EmptyState | 说明授权范围内没有读到什么，不推断现实不存在；提供有依据的下一步 |
| LoadingState | 不提前出现成功文案，不用上次数据冒充本次完成 |
| ErrorState | 说明可理解的原因与正常恢复入口，保留原对象/版本与历史结果 |

组件名只是设计职责，不要求本批创建所有React组件或新的组件框架。优先复用现有组件与投影，真正重复或不一致的部分在相应阶段再收敛。

视觉延续黑白、简洁、低装饰、少卡片和清晰层级。字号、间距、按钮尺寸及状态用语统一，不堆粗边框、彩色标签和技术说明。同一种状态、按钮或返回关系不能因页面不同形成不同语义。

## 各阶段产品交付

| 阶段 | 主要产品表面 | 必须一起解决的状态/操作 |
| --- | --- | --- |
| P4 Plan Experience | 计划列表/详情，关联日程与会话 | 目标、进展、下一步、发现、待处理、检查/历史、暂停/恢复/结束/版本；九种真机状态 |
| P5 Service Runtime | 服务，关联日程/计划/会话 | 发现/详情/能力、请求/确认、接受/拒绝/完成/取消、待履约与问题处理 |
| P6 Skill Composition | 计划→Skill仓库/我的计划，会话 | 仓库/方法搜索详情、来源/版本、所需信息/能力/限制、用于当前需求/开始会话、冻结引用 |
| P7 Provider/MCP | 资源→本机/云端/其它设备/接口 | 连接/断开、授权过期、权限不足、健康、能力范围、新鲜证据、选目标/恢复 |
| P8 Android UI Agent | App资源，会话/计划及审批 | 可读/可做、App版本、权限与最近验证，解释将在哪个App做何操作 |
| P9 Windows | 资源→其它设备，会话/计划 | 在线/离线、能力权限、可操作范围、心跳/真实证据、重连后的原目标继续 |
| P10 Cloud/Synthesis | 五页内按对象归属 | 新能力候选、待授权、受控启用与新PlanVersion；不增加Cloud一级页 |
| P11 Final Closure | 五页和全部二三级页 | 全局字号/间距/导航/列表/按钮/状态/隐私/无障碍走查，修复不一致，不增功能 |

“九种真机状态”指运行中、WAITING_RESOURCE、VERIFIED_EMPTY、Candidate待核实、Truth有效、Approval待处理、结果核对中、暂停、结束，具体语义见 [P4设计](P4_PLAN_EXPERIENCE_DESIGN.md)。业务状态只在有真实依据时呈现，不为截图制造生产事实。

## 只读投影与操作权威

用户表面消费现有Authority的owner/version受控Projection。展示状态不反向写Plan、Truth、Approval或Runtime；触发操作仍走既有确认、审批、版本和授权合同。

主表面不显示Invocation、Ledger、epoch、Worker、lease、Target IDs或原始技术日志。必要解释以用户动作和现实证据为中心，避免把协议成功写成“事情完成”。已失效的来源/Truth不能继续支持当前结果；历史证据仍保留当时状态。

当前提醒边界为持久化站内提醒，Android OS Push另行记账。普通USER_EVENT不被变成Plan；Skill不被变成Resource；Service接受不被当作履约完成；未知副作用不提供盲目重试快捷入口。

## 阶段记录与关闭

每个阶段记录受影响页面、对应Contract/API Projection、用户状态及可用操作、错误/恢复路径、自动验证、真实设备/账号/服务、截图/操作记录、现实验证和已知限制。测试证据与真实证据分开，截图不能单独证明副作用或Truth。

产品轨道与后端轨道在同一阶段联调；Contract DoD、Runtime DoD、Product DoD、Real Evidence DoD全部满足，再按 [总计划关闭Gate](V83_MAINLINE.md#前后端开发次序与统一关闭gate)更新状态/ledger。P11完成所有二三级页总走查；若产品保留深浅色，两套均验证。

无依赖工作可以按当前阶段许可并行，但不能让移动端落后多个阶段，也不能把本轨道变成跳过P3剩余三个真实验收项的理由。
