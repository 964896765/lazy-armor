# Auth V2 · M2-03 已验证邮箱统一密码恢复

日期：2026-10-13。基线9edda3fe，codex/v83-persistent-runtime。范围：已验证原邮箱及安全绑定的新邮箱恢复同一用户级密码、恢复链接隔离、原子撤销登录会话和同步产品入口。零新SQL，复用password_reset_tokens、password_credentials、原User ID与业务归属。完整M2、正式灰度、短信和Passkey仍分别待完成。

## 账号与产品行为

在BOUND模式下，已有密码用户可以用任一已验证登录邮箱申请恢复。登录标识与旧密码身份的历史归属冲突、未验证邮箱、禁用账号及无密码账号不发送恢复链接；无密码用户仍可验证码登录，不隐式创建密码。不凭另一邮箱已验证而提升未验证旧邮箱，不创建或合并用户。

GET /auth/methods返回passwordRecovery.available/emailAliases，安全中心逐个邮箱返回recoveryEnabled；只在有密码、合法已验证归属、发送开关与HTTPS恢复网关可用时显示实际恢复能力。找回页按服务端能力区分原邮箱/任一已验证邮箱，无服务时提示验证码登录；失效页提供重新申请。修改密码页新增邮箱恢复入口，已登录及待引导用户均可打开找回/重置页面，服务端恢复证明仍是改密权威，客户端登录态不能替代链接。

重置后新邮箱和原密码标识使用同一个新密码进入原账号，原未验证邮箱的状态保持。后台仅撤销该账号的登录会话，Goal、Memory、Plan、History、订阅、角色与其他账号归属不迁移。Runtime付款、群发、删除等独立审批不因恢复密码而授予。

## 加密链接与旧读者隔离

新链接使用v2前缀和AES-256-GCM认证加密，12字节随机IV、256位随机nonce；通过HKDF从服务端JWT_SECRET派生独立加密密钥，并固定恢复用途AAD。密文冻结用户、渠道类型/ID/已验证归属指纹、密码凭据ID/来源/hash/version指纹及到期时间，严格校验版本、类型、规范base64url与长度。仅指纹进入加密上下文，不携带密码、bcrypt hash或明文邮箱，公开接口不返回上下文或原链接。

SQL仍只保存64位token_hash、User ID、有效期与单次消费状态。V2 token_hash使用有独立用途前缀的HMAC-SHA256；旧读者计算的普通SHA256无法找到V2记录，所以旧代码也不能绕过冻结上下文消费新版链接。新版LEGACY读者主动拒绝v2，BOUND读者拒绝所有旧格式；新增邮箱或后来验证原邮箱都不会使旧链接在BOUND模式下重新生效。

默认有效期沿原配置1800秒；SQL到期时间必须与加密上下文一致，消费时再次检查服务端时间。修改密码、改变凭据版本、渠道重建/改址/验证状态/归属变化、账号禁用或换钥使旧链接不可用。旧密码镜像在回填中产生新的凭据ID也可能让在途链接失效，灰度前应完成回填并在安全信息变化后重新申请。

## 接口、预算与事务

| 接口/阶段 | 条件与结果 |
| --- | --- |
| POST /auth/forgot-password | 规范化邮箱后解析已验证归属；未知/未验证/禁用/冲突/无密码/限频/发送失败统一requested=true，不回传token |
| 发送预算 | 邮箱3次/900秒、IP10次/900秒、原用户3次/900秒；用户预算跨不同邮箱共享 |
| 签发 | HTTPS网关发送且禁止重定向；随后锁渠道/原用户并重查指纹，撤销该用户先前链接、写入新hash和成功审计同事务 |
| POST /auth/reset-password | IP30次/300秒；存在且未消费的合法令牌最多5次/300秒，计算bcrypt前限制昂贵工作；最大1024字符和原bcrypt72字节密码上限 |
| 消费 | 校验认证密文、SQL用户/有效期，事务内锁定并重查源邮箱与凭据；原子claim→两密码表/版本→全登录会话及恢复链接撤销→成功审计 |

发送位于数据库重试事务之外，避免锁内外部调用和重试发邮件。发送失败不产生可用token，也不撤销已有合法链接。发送成功后证明变化或SQL/审计失败可能使已送达链接不可用，需要重新申请；签发事务回滚不留下半条token或错误撤销旧链接。消费审计失败时，两表密码/版本、token、会话撤销全部回滚，仍合法且未过期的链接可在预算内重试。

同一用户锁串行化不同别名签发和重置：最后成功签发的链接保留，重复/并发消费成功一次。密码计算在事务外，最终密码/渠道证明在事务内重查，阻止邮件期间变更和旧密码/刷新请求补发会话。Redis或内部错误停止操作并返回脱敏错误。统一回包不作为完整时序侧信道、机器人或供应商防滥用验收。

## 灰度与回滚

| 配置 | 行为 |
| --- | --- |
| AUTH_PASSWORD_RECOVERY_MODE=LEGACY（默认） | 保留原已验证canonical邮箱路径，不支持邮箱别名；拒绝v2链接 |
| AUTH_PASSWORD_RECOVERY_MODE=BOUND | 要求AUTH_PASSWORD_CREDENTIAL_MODE=UNIFIED及0093可读；已验证邮箱别名共享密码恢复，只消费新格式 |
| AUTH_PASSWORD_RECOVERY_REQUEST_ENABLED=false | 停止新请求发送并显示不可用，保持BOUND校验与已签发合法链接的消费，不降级到旧规则 |

先全量部署兼容代码、审计/回填0093凭据，排空旧请求并统一BOUND配置，再灰度新入口与真实供应商。每环境独立记录旧格式恢复链接拒绝及新链接成功证据。回滚应停发并保持BOUND读取；退回LEGACY或旧代码会丢失别名恢复能力，旧格式链接也可能重获旧验证路径，不作为安全回滚。V2的SQL hash隔离继续阻止旧读者解释新版链接。

JWT_SECRET换钥会使旧密文及HMAC查找失效；生产需统一密钥、发布和回滚策略。恢复旧备份后必须按认证恢复程序换钥并撤销原登录会话/旧恢复链接，不能把数据库恢复摘要一致当作已解决历史token重放。本人库本批不迁移、不回填、不改角色或安全标识，不部署/安装新APK。恢复网关仍发送既有lazyarmor原生深链；正式邮件送达、真实深链及Web邮件HTTPS目标需要独立验收。
