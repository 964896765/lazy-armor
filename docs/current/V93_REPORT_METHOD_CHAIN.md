## 用户可见结果

新受理的合规报告组合由原队列依次完成最多三个方法。上游已保存的输出字段进入下游输入，不再只把方法说明加入最终写作提示词。报告页可展开每个方法的实际输入、输出与使用的来源编号，会话卡片显示已保存的方法数。生成中显示「正在逐项生成方法成果」。

旧 `REPORT_GUIDANCE_V1` 持久报告保持原参考语义，不把旧记录改称已执行方法。新链仍只支持原适配器允许的公开读取、文本分析与报告交付，不开放手机动作、文件写入或任意工具。

## 边界与数据校验

- 方法采用原账号启用的确切版本及内容 hash，受理、计算、保存和交付沿原组合权威复核。
- 输入只来自本次需求中的用户声明/明确假设或已经保存的直接上游字段。保留数值零和布尔 false，不把字符串自动转成金额或布尔值。
- 每个方法只看到自己的固定公开来源、直接上游引用的资料，以及本次用户附件/程序计算；不引入无关分支来源。
- 输出严格符合声明的基础字段类型；链接及交付所需字段必须有值。拒绝额外字段、未知/重复来源编号、未声明的引用与未取得的原文链接。
- 每个保存结果包含真实输入、输出、来源编号、输入/来源/输出 hash、模型标识及检查时间。单项字段与总文本长度都有上限。
- 方法说明、自动提示词及资料作为非可信输入，不能扩大资源权限或执行范围。
- 最终正文、首次检查、修订及第二次检查均消费同一组已保存方法结果。

保存结果明确标为 `CONTRACT_CHECKED_ONLY`、`MODEL_GENERATED_UNVERIFIED` 和 `semanticVerified=false`。字段、引用及完整性校验不证明事实、算术、业务效果或个人 Truth，也不保证模型确实遵守了方法说明的所有语义要求。

## 持久化与恢复

新增 COMPOSING 阶段纳入原报告恢复扫描，不另建 Worker、执行记录或数据库表。每次模型调用沿原 revision fence 和持久预算预留额度，保存结果时在事务内复核原组合与资源授权。关闭方法、撤权、原条件变化或篡改已保存结果会阻止继续生成与发布。

恢复时必须是原拓扑顺序的连续结果前缀，逐项重算输入、方法内容、来源及输出 hash。已经保存的前序结果复用，下游重新尝试仍计入原预算。进入正文阶段必须有完整结果。调用完成但保存前进程退出时可能重新调用该节点；没有承诺模型调用 exactly-once。

每任务继续使用原 20 分钟、16 次请求和 131072 预留输出 token 限额，实际 provider 用量单独记录。合同纠正最多一次，结构性字段失败也进入有界纠正提示。人民币价格及费用上限仍未实现。
